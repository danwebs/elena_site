# Сайт дизайнера интерьеров Елены Габдрафиковой — тема «Графит»

Одностраничный статический сайт: HTML + CSS + чистый JavaScript, без фреймворков, библиотек, баз данных и серверного кода.

## Структура

```
elena-site/
├── index.html              — главная (все блоки сайта)
├── privacy.html            — политика обработки персональных данных (для самозанятой)
├── 404.html                — страница «не найдено»
├── robots.txt, sitemap.xml — для поисковиков (заменить домен)
├── CNAME.example           — заготовка под свой домен
├── .nojekyll               — чтобы GitHub Pages отдавал файлы как есть
├── .well-known/security.txt— контакт для сообщений об уязвимостях
├── deploy/nginx.conf.example — настройки безопасности для будущего хостинга
└── assets/
    ├── css/  fonts.css, style.css
    ├── js/   data.js (проекты, стили, тест), main.js (логика)
    ├── fonts/ локальные шрифты Manrope и Cormorant Garamond (лицензия OFL)
    └── img/  hero, elena, before/after, projects/, styles/
```

## 1. Запуск на своём компьютере

Из-за защитной политики безопасности (CSP) сайт нужно открывать через локальный сервер, а не двойным щелчком.

**Вариант А — Python (есть на macOS/Linux, на Windows ставится с python.org):**
```bash
cd elena-site
python3 -m http.server 8000      # на Windows: py -m http.server 8000
```
Откройте в браузере: http://localhost:8000

**Вариант Б — VS Code:** установите расширение «Live Server», откройте папку и нажмите «Go Live».

## 2. Публикация на GitHub Pages (бесплатно)

1. Зарегистрируйтесь на https://github.com и **включите двухфакторную аутентификацию** (Settings → Password and authentication).
2. Создайте репозиторий: «New repository» → имя, например `elena-design` → Public → Create.
3. Загрузите файлы: «Add file → Upload files» → перетащите **содержимое** папки `elena-site` (не саму папку) → «Commit changes».
   Скрытые папки `.well-known` и файл `.nojekyll` проще загрузить через GitHub Desktop или git:
   ```bash
   cd elena-site
   git init && git add . && git commit -m "Первая версия сайта"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/elena-design.git
   git push -u origin main
   ```
4. Settings → Pages → Source: «Deploy from a branch» → Branch: `main`, папка `/ (root)` → Save.
5. Через 1–2 минуты сайт будет доступен по адресу `https://ВАШ_ЛОГИН.github.io/elena-design/`.
6. Там же включите **Enforce HTTPS**.

Обновление сайта: измените файлы → загрузите снова (или `git add . && git commit -m "..." && git push`).

## 3. Подключение домена (когда появится)

1. Купите домен у российского регистратора (REG.RU, RU-CENTER, Timeweb и др.).
2. Переименуйте `CNAME.example` в `CNAME` и впишите в него домен, например `gabdrafikova.ru`.
3. У регистратора в DNS добавьте A-записи на IP GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` и CNAME-запись `www` → `ВАШ_ЛОГИН.github.io`.
4. В Settings → Pages укажите домен в «Custom domain» и включите «Enforce HTTPS».
5. Замените `example.ru` на свой домен в файлах: `index.html` (canonical, og:image, JSON-LD), `robots.txt`, `sitemap.xml`, `.well-known/security.txt`.
6. Добавьте сайт в Яндекс Вебмастер (webmaster.yandex.ru) и отправьте `sitemap.xml`.

**Рекомендация:** вместе с доменом перенесите сайт на российский хостинг (Timeweb, Beget, REG.RU и т.п.) и примените `deploy/nginx.conf.example` — так можно задать полные защитные HTTP-заголовки, а данные о посещениях будут храниться в РФ.

| Что | Где |

| Проекты портфолио | `assets/js/data.js` → `PROJECTS` + фото в `assets/img/projects/` |
| Отзывы | `index.html`, блок `#reviews` — вставить реальные и **удалить метки «пример»** |
| Дата редакции политики | `privacy.html` |

Сейчас все фотографии — сгенерированные демо-изображения. Замените их реальными работами из Instagram.

### Как добавить проект
В `assets/js/data.js` скопируйте любой блок в `PROJECTS` и измените поля:
```js
{ id: "p12", title: "Название", kind: "Реализация",   // или "Визуализация"
  style: "scandi",   // classic | modern-classic | minimal | scandi | avantgarde | industrial
  city: "Туймазы", area: "60 м²", term: "3 месяца",
  images: ["assets/img/projects/p12-1.jpg", "assets/img/projects/p12-2.jpg"],
  task: "Задача клиента…", solution: "Как решили…" },
```
Имена файлов фото — только латиница, цифры, `-` и `_` (иначе фото не покажется: это защита). Перед загрузкой уменьшите фото до ~1200 px по длинной стороне (например, на squoosh.app) — сайт будет загружаться быстрее.

### Как изменить тест
В `data.js`: `QUIZ` — вопросы и варианты (числа = баллы стилям), `STYLES` — описание, палитра, планировочные решения и идеи для каждого из 6 стилей.

## 5. Безопасность

Сайт статический: у него нет админки, базы данных, форм и серверного кода — поэтому основные способы взлома (SQL-инъекции, подбор пароля к админке, уязвимости CMS и плагинов) к нему неприменимы.

Что сделано в коде:
- **Content Security Policy** — браузер выполняет только скрипты, стили, шрифты и картинки самого сайта; внешние скрипты, фреймы, формы и встроенный код запрещены.
- **Защита от XSS** — весь динамический контент создаётся через `textContent`/`createElement`, `innerHTML` не используется; пути к фото и цвета палитры проверяются по шаблону.
- **Защита от кликджекинга** — сайт нельзя встроить в чужой фрейм (скрипт + `frame-ancestors` в nginx-примере).
- **Внешние ссылки** открываются с `rel="noopener noreferrer"`; `Referrer-Policy` ограничивает передачу адреса.
- **Ни одного стороннего сервиса**: шрифты лежат локально, нет счётчиков, виджетов и CDN — нечему «протечь» и нечего взломать через подрядчика.
- HTTPS обязателен (`upgrade-insecure-requests`, «Enforce HTTPS»).

Что нужно сделать вам:
- включить двухфакторную аутентификацию на GitHub и у регистратора домена;
- не хранить в репозитории пароли, ключи и личные документы;
- при переходе на свой хостинг использовать `deploy/nginx.conf.example` (HSTS, X-Frame-Options, X-Content-Type-Options, Permissions-Policy).
